# Library Accounting — учёт выдачи книг

Учебный программный модуль для библиотеки: каталог книг, регистрация читателей, выдача, возврат и продление книг, контроль просрочек.

Проект выполняется в рамках учебной практики **МДК 02.02 «Инструментальные средства разработки программных модулей»**.

> Вариант предметной области выбран командой условно («Библиотека: учёт выдачи книг»). Если руководитель практики выдал другой вариант — замените описание в `docs/analysis.md` и диаграммы в `docs/uml.md`, структура репозитория остаётся прежней.

## Команда и роли

| Роль | Участник | Зона ответственности |
|------|----------|----------------------|
| Тимлид / Интегратор | _ФИО участника 1_ | Декомпозиция задач, ревью, слияние веток в `main`, ведение Kanban-доски |
| Разработчик | _ФИО участника 2_ | Реализация задач в feature-ветках, коммиты, push |
| Тестировщик | _ФИО участника 3_ | Модульные тесты в `tests/`, проверка задач в колонке Review |

## Быстрый старт

Требуется Python 3.10+ (внешние зависимости не нужны).

```bash
git clone <адрес общего репозитория> library-accounting
cd library-accounting
python -m unittest discover -s tests -v
```

## Рабочий процесс (кратко)

1. Задача берётся с Kanban-доски (колонка **To Do** → **In Progress**).
2. Для задачи создаётся ветка от `main`: `git switch -c feature/<краткое-имя>`.
3. Изменения фиксируются коммитами в формате `тип: описание` (`feat:`, `fix:`, `docs:`, `test:`, `chore:`).
4. Ветка отправляется в общий репозиторий: `git push -u origin feature/<краткое-имя>`.
5. Карточка переносится в **Review**; тимлид проверяет и сливает ветку в `main`, карточка уходит в **Done**.

Подробности — в [`docs/team-access.md`](docs/team-access.md) и [`docs/kanban.md`](docs/kanban.md).
