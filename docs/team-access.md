# Доступы и правила работы с Git

## 1. Общий репозиторий

В учебной работе использован **удалённый (bare) репозиторий** `remote/library-accounting.git`, созданный командой:

```bash
git init --bare --shared=group -b main library-accounting.git
```

Участники клонируют его и работают в своих локальных копиях:

```bash
git clone <адрес общего репозитория> library-accounting
git config user.name  "Фамилия Имя"
git config user.email "почта@example.com"
```

При использовании GitHub или GitLab вместо bare-репозитория создаётся проект на сервисе, а `<адрес общего репозитория>` — его URL.

## 2. Права участников

| Роль | GitHub | GitLab | Что разрешено |
|------|--------|--------|---------------|
| Тимлид / Интегратор | Admin | Maintainer | Слияние в `main`, управление доступами, настройка защиты веток |
| Разработчик | Write | Developer | Создание веток, push в feature-ветки, запросы на слияние |
| Тестировщик | Write | Developer | Push тестов в свои ветки, комментарии при ревью |

Как выдать доступ:

- **GitHub:** Settings → Collaborators → Add people → выбрать роль.
- **GitLab:** Project information → Members → Invite members → выбрать роль.
- **Локальный сервер:** добавить участников в одну группу ОС и выдать группе права на каталог репозитория (`--shared=group`).

## 3. Защита основной ветки

Для ветки `main` включить:

- запрет прямого push (изменения только через запрос на слияние);
- обязательное одобрение тимлида;
- запрет принудительного push (`--force`).

## 4. Именование веток

| Тип | Шаблон | Пример |
|-----|--------|--------|
| Новая функциональность | `feature/<кратко-латиницей>` | `feature/book-catalog-stub` |
| Исправление | `fix/<кратко>` | `fix/loan-due-date` |
| Документация | `docs/<кратко>` | `docs/uml-update` |

## 5. Формат сообщений коммитов

Формат: `тип: краткое описание в повелительном наклонении`.

| Тип | Назначение |
|-----|-----------|
| `feat` | новая функциональность |
| `fix` | исправление ошибки |
| `docs` | документация |
| `test` | тесты |
| `chore` | служебные изменения (структура, настройки) |

Примеры: `feat: add book catalog stub`, `docs: add UML diagrams`.

## 6. Порядок работы над задачей

```bash
git switch main
git pull
git switch -c feature/<имя-задачи>
# ... работа над кодом ...
git add <файлы>
git commit -m "feat: ..."
git push -u origin feature/<имя-задачи>
```

После push карточка переносится в **Review**. Тимлид проверяет изменения, сливает ветку в `main` и переносит карточку в **Done**.
