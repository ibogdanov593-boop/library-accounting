# Анализ предметной области: учёт выдачи книг в библиотеке

## 1. Цель системы

Автоматизировать работу библиотекаря: вести каталог книг, регистрировать читателей, оформлять выдачу, возврат и продление, а также выявлять просрочки.

## 2. Распределение ролей в команде

| Роль | Задачи на практике |
|------|--------------------|
| Тимлид / Интегратор | Анализ задания, декомпозиция, ведение доски, ревью и слияние веток |
| Разработчик | Реализация модулей в feature-ветках |
| Тестировщик | Написание и запуск тестов, проверка карточек в колонке Review |

## 3. Актёры (пользователи системы)

| Актёр | Описание |
|-------|----------|
| Читатель | Ищет книги, просматривает свои выдачи |
| Библиотекарь | Оформляет выдачу, возврат и продление, регистрирует читателей |
| Администратор | Управляет каталогом книг, формирует отчёты |

## 4. Основные сущности

| Сущность | Ключевые атрибуты |
|----------|-------------------|
| Книга (Book) | ISBN, название, автор, год издания, всего экземпляров, доступно экземпляров |
| Читатель (Reader) | номер билета, ФИО, телефон, признак блокировки |
| Выдача (Loan) | номер, книга, читатель, дата выдачи, срок возврата, дата возврата, число продлений |

## 5. Бизнес-правила

| № | Правило |
|---|---------|
| BR-1 | Книгу можно выдать, только если есть хотя бы один доступный экземпляр |
| BR-2 | Один читатель может иметь не более 5 книг одновременно |
| BR-3 | Стандартный срок выдачи — 14 дней |
| BR-4 | Выдачу можно продлить один раз на 7 дней, если срок ещё не истёк |
| BR-5 | Читателю с просроченной книгой новые книги не выдаются |
| BR-6 | При возврате счётчик доступных экземпляров увеличивается на 1 |
| BR-7 | ISBN в каталоге уникален |

## 6. Функциональные требования

| № | Требование | Актёр |
|---|-----------|-------|
| FR-1 | Добавление, поиск и удаление книг в каталоге | Администратор, Читатель (поиск) |
| FR-2 | Регистрация читателя | Библиотекарь |
| FR-3 | Выдача книги читателю | Библиотекарь |
| FR-4 | Приём возвращённой книги | Библиотекарь |
| FR-5 | Продление выдачи | Библиотекарь |
| FR-6 | Список читателей с просрочкой | Администратор |
| FR-7 | Просмотр текущих выдач читателя | Читатель, Библиотекарь |

## 7. Нефункциональные требования

- Модуль работает без внешних зависимостей (стандартная библиотека Python).
- Бизнес-логика отделена от пользовательского интерфейса и хранилища.
- Каждая функция покрывается модульным тестом.

## 8. Границы первой итерации

В первой итерации реализуются заглушки и минимальная логика каталога, регистрации читателей, выдачи и возврата. Хранение данных — в памяти. Интерфейс, база данных и штрафы выносятся в бэклог.
